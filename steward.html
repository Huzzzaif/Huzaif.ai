The problem

A column changes upstream. A model behaves differently downstream. Understanding the connection requires tracing dependencies, and the next person may repeat the same investigation.

What I built

Two agents with complementary jobs: one investigates the downstream impact of a proposed change, while the other traces upstream to identify possible root causes. Both read existing findings and write new evidence back into DataHub.

The engineering decision

Keep findings in the catalog itself, where another person or agent can reuse them. A shared adapter separates catalog access from agent logic, with GraphQL integration and a FastAPI streaming interface.

The result

Findings compound: each investigation leaves evidence the next one can reuse. Results depend on the model, question, catalog state, and code version. The hosted demo uses an in-memory catalog; live DataHub integration was validated separately.
